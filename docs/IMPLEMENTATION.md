# 実装指示と完了条件

参考: https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/

記事の Altitude / Depth / Range を、機能を増やすためではなく次の実装指示に落とし込む。

> 写真を選ぶ、並べる、調整する、1枚に保存する流れを、PCとスマホのどちらでも短く確実に完了できるようにする。課金、透かし、ログイン、写真のアップロードを必要としない。グリッドと自由配置を用意し、プレビューと書き出しに同じ描画処理を使用する。画像の向き、大きさ、透明部分、読めないファイル、保存失敗、タッチ操作を実際の入力と出力で検証する。UIは写真を主役とし、補足と細かい調整は必要な時に開く。写真のプライバシー、端末メモリ、アクセシビリティも具体的な実装と検証に反映する。公開URLから主要操作ができるまで完了としない。

## 判断

- 空の作業フォルダから新規作成。HTML / CSS / JavaScript / Canvas 2D。配信にビルドや外部ライブラリは不要。
- GitHub Pagesで静的公開。画像はブラウザで処理し、編集途中はそのブラウザのIndexedDBに保存。
- 最大12枚。画像は読込時に長辺4096px以内に縮小し、合計画素数にも上限を設ける。履歴は画像本体を複製せず編集値だけを保存。
- PNG / JPEG、長辺1080 / 2048 / 4096px。PNGは透明背景対応。JPEGの透明部分は白にする。
- 同一のCanvas描画関数で表示と出力を生成。選択枠は別のオーバーレイとして描き、出力には含めない。
- 補助ライブラリは開発用のPlaywrightだけ。単体テストはNode標準テスト。

## 完了条件

- 画像追加、複数レイアウト、縦横比、位置・倍率・回転、並べ替え、余白・角丸・背景、自由配置、取消・やり直し、下書き復元、保存。
- 不正画像、画像上限、ストレージ失敗、書き出し失敗をユーザーに分かる形で扱う。
- レイアウトの幾何学と画像出力を自動検証し、PC / iPhone 14相当の画面で操作する。
- 公開後にURL、配信ファイル、主要操作を確認。実機未検証の場合は区別して報告する。
